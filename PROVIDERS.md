## PayPal details

**Browser (JS SDK v6)** — `loadCoreSdkScript({ environment: 'sandbox' })` from `@paypal/paypal-js/sdk-v6` loads `https://www.sandbox.paypal.com/web-sdk/v6/core`; then `paypal.createInstance({ clientId, components: ['paypal-payments'], pageType: 'checkout' })`, `findEligibleMethods({ currencyCode: 'USD' })`, `createPayPalOneTimePaymentSession({ onApprove, onCancel, onError })`, and on the user's click `session.start({ presentationMode: 'auto' }, createOrderPromise)` (the promise is not awaited before `start`, as PayPal's sample requires, to keep transient activation). The `<paypal-button>` web component is PayPal's.

**Server (REST)** — `POST /v1/oauth2/token`; `POST /v2/checkout/orders` (`intent: CAPTURE`, `purchase_units[0].reference_id/custom_id/description/amount`, `payment_source.paypal.experience_context` with `shipping_preference: NO_SHIPPING`, `user_action: PAY_NOW`, return/cancel URLs; `PayPal-Request-Id` for idempotency; `Prefer: return=representation`); `POST /v2/checkout/orders/{id}/capture` (`PayPal-Request-Id`); `GET /v2/checkout/orders/{id}`; `POST /v1/notifications/verify-webhook-signature` with the raw event embedded verbatim. Handled webhook events: `CHECKOUT.ORDER.APPROVED`, `CHECKOUT.ORDER.COMPLETED`, `CHECKOUT.PAYMENT-APPROVAL.REVERSED`, `PAYMENT.CAPTURE.COMPLETED|PENDING|DENIED|DECLINED|REFUNDED|REVERSED` (PayPal documentation uses both DENIED and DECLINED naming; both are handled).

**Agent Toolkit / MCP** — evaluated `@paypal/agent-toolkit@1.11.0` (tools include `create_order`, `get_order`, `pay_order`, invoicing, subscriptions). It is **not** embedded in the Worker because (a) its dependencies (axios, langchain, openai, mathjs, dotenvx) are not Workers-friendly and (b) WorldLens deliberately gives the model **no** money-moving tools. The equivalent read-only capability is our `get_payment_status` tool, which calls the same Orders API (`GET /v2/checkout/orders/{id}`). Developers can still use PayPal's MCP server from their IDE for sandbox inspection; see MANUAL_SETUP.md.

## Anthropic details

`client.beta.messages.create` with `model` (default `claude-opus-5-5` strong / `claude-haiku-5-5` fast), `output_config.effort` (`medium` agent, `low` summaries/framing), top-level `cache_control: {type:'ephemeral'}` (stable tool list + frozen system prompt are the cached prefix; app state goes in the last user turn), and for Opus/Sonnet/Fable models `betas: ['server-side-fallback-2026-07-01'], fallbacks: 'default'` (refusal fallback routing). Stop reasons `tool_use`, `pause_turn`, `max_tokens`, `refusal` are handled. Tool results for one turn are returned in a single user message; invalid calls get `is_error: true`.

Cost control: per-model price table (`apps/api/src/ai/budget.ts`, unknown models priced at the highest rate), daily spend cap (`AI_DAILY_BUDGET_USD`), per-client rate limit (`AI_REQUESTS_PER_MINUTE`), output caching for framing/summaries, usage at `GET /api/ai/usage`.

## Verification notes and uncertainty

- The build environment could not reach `docs.paypal.ai`, `developer.paypal.com`, GDELT, Wikipedia or MapTiler over HTTP. PayPal behaviour was verified from PayPal's official npm package types, PayPal's official GitHub sample and OpenAPI repositories. MapTiler endpoint names come from MapTiler's documentation (via search); the imagery URL template is read at runtime from TileJSON rather than assumed.
- GDELT parameters follow the long-standing DOC 2.0 API; GDELT's own blog could not be fetched. Responses are validated and failures degrade gracefully.
- **No live call to PayPal, GDELT, Wikipedia, MapTiler or Anthropic was executed from this environment.** Those paths are covered by unit/integration tests with faithful test doubles and must be confirmed with real credentials (see HACKATHON.md checklist).
